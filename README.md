# 执行申请材料助手 · v1.1

本地优先的执行申请材料整理工具。v1.1 新增 PDF 逐页 OCR、图片 OCR 和案件字段自动填入，所有字段始终可由用户修改。适用于一个申请人、一个被执行人的限定场景，输出供人工核对的材料草稿，不是已审核的法院提交文件。

本仓库仅包含应用源码、依赖配置、测试、构建脚本及说明。需求文档、独立演示页面、设计图、参考资料、原始案件材料、测试附件和本地导出文件不纳入版本管理；这些本地文件不会因此被删除。版本变更和验收记录见 [更新日志](CHANGELOG.md)。

## 使用入口

在线入口：[打开执行申请材料助手](https://execution-application-assistant.vercel.app/)。线上版本以 Vercel 成功部署的提交为准；源码推送成功不等于线上完整功能回归通过。

启动后的本机网页：[打开本机版本](http://127.0.0.1:4173/)。此地址仅在本机服务运行时有效，不是公开网站。

下载或克隆仓库后，在仓库根目录运行：

    npm ci
    npm run dev -- --port 4173

推荐 Node.js 24 LTS，最低按构建工具要求使用 20.19 至 20.x 或 22.12 及以上；本次测试使用 24.19.0 和 25.8.1。若 npm 默认缓存没有写入权限，可给 npm ci 指定可写的 --cache 目录。Windows 实机尚未验收。

启动和构建前会自动从锁定的依赖复制 OCR 程序、中英文模型、TIFF 解码器和 PDF 渲染资源到 public/ocr/，运行时不使用公共 CDN 或云端 OCR。发布时必须部署完整 dist/，不能只上传 index.html。

### 本地运行包

运行 `npm run build:offline` 生成 output/ 下的 v1.1 ZIP。本包包含完整网页、OCR 程序和模型，解压后运行 `node start.mjs`，再打开提示的本机地址；端口冲突时可使用 `node start.mjs 4177`。启动器只监听 127.0.0.1，只提供静态资源，不接收案件文件。

v1.1 不再生成单文件 HTML：OCR 需要独立的 Worker、WASM 和模型文件。旧 `build:single` 命令会提示改用本地运行包，不覆盖已有 v1.0 产物。不要直接双击包内的 HTML；file:// 模式不在支持范围。

## 五步使用

1. **适用范围**：主动回答前四题；第五题默认“否”。第五题为“是”仍可继续整理材料，但不启用复杂项目自动计息。页面导航不会绕过导出检查。
2. **案件信息**：选择材料并点击“OCR识别并自动填入”，或直接手填。符合规则且无冲突的候选自动填入空白字段，保留文件名、页码和原文片段。低分或不明确的候选由用户决定是否采纳。填写并核对拟申请执行法院，然后确认案件字段。
3. **金额试算**：选择“只整理本金”或“单本金固定年利率试算”，写明金额及口径依据，计算后确认。修改本金会同步案件页；任何相关修改都会使旧确认失效。
4. **文书与材料**：核对完整预览和附录，勾选材料清单并确认草稿性质后下载真实 DOCX 或 ZIP。清单勾选只记录用户操作，不证明材料有效或已经上传。
5. **官方填报**：逐项复制当前确认信息，再由本人进入人民法院在线服务网认证、上传和提交。工具不携带案件参数跳转，不代管账号、密码、验证码或 Cookie。

请在关闭或刷新前点击“保存本地草稿”，并确认下载文件确已保存。所有步骤均可保存草稿；应用不会自动持久保存案件内容。浏览器可能缓存程序资源，OCR 语言模型单独缓存在 IndexedDB 中，见下方隐私说明。

## 材料读取范围

每类最多 1 份，共一审文书、二审文书、身份证明或主体材料 3 类；每份最多 20 MB。

| 格式 | 本版行为 | 主要限制 |
| --- | --- | --- |
| PDF：扫描、文本及混合页面 | PDF.js 将每页渲染成图片，再由 Tesseract.js OCR，保留真实页码 | 最多 50 页、50 万字符；加密文件要求用户自行解锁；损坏、超时或空白材料明确报错 |
| JPG / JPEG / PNG / WebP / BMP | 本机解码、纠正支持的图片方向并 OCR | 每张最多 2500 万像素，单边不超过 16000 像素；动态 WebP 不支持 |
| TIF / TIFF | 本机逐页解码并 OCR，支持多页文件 | 最多 50 页，每页同样受像素限制；已测试 LZW 和 Group 4 黑白编码，其他编码及方向标签兼容性未逐一验收 |
| DOCX | 读取正文段落和表格中的文字，保留段落序号 | 正文 XML 最多 2 MB、5000 段、50 万字符；异常解压规模和修订文档拒绝解析；页眉、图片及其他部分不计入已解析正文 |
| UTF-8 TXT | 按非空行读取，保留原行号 | 最多 5000 个非空行、50 万字符；其他编码提示另存 |
| 旧 DOC、HEIC、GIF、SVG 等 | 不直接识别 | 旧 DOC 另存 DOCX 或 PDF；其他图片先转 PNG、JPG 或 PDF；改扩展名不能转换格式 |

OCR 使用 GitHub 上的 [Tesseract.js 7.0.0](https://github.com/naptha/tesseract.js)，配合 [PDF.js](https://github.com/mozilla/pdf.js) 和 [UTIF.js](https://github.com/photopea/UTIF.js)。识别以简体中文和英文印刷体为主；手写、印章遮挡、低清照片、复杂表格或版面可能漏读、误读。DOCX 只提取正文，不对内嵌图片逐张 OCR；请先导出 PDF。原文件始终是核对依据。

### 自动填入与人工修改

- 提取明确写出的法院、文书类型、案号、生效日期、本金，以及执行角色对应的姓名、主体类型、电话、地址、证件号码；明确标注的执行法院、请求简述和财产线索也可提取。
- OCR 行参考分数至少 75/100、格式有效、没有同字段不同值、目标为空且未被用户主动编辑时，才自动填入。参考分数不是准确率，也不是法律审核。
- 一批材料全部读取后再判断冲突；不同数值同时保留，不能让第一份文件先占据空白字段。`100000` 和 `100000.00` 视为同一金额。
- 用户可以修改或清空任意字段。识别期间的修改、重复识别、换文件、保存后恢复，均不会自动覆盖用户已编辑的字段；主动点击候选仍可采纳，替换已有不同值时需确认。
- 原识别值及其来源会保留，便于比较。所有自动填入内容仍须人工核对，修改上游信息会撤销原有金额及导出确认。
- 不从“原告/被告”推定执行角色，不把普通日期当作生效日期，不推断管辖。无明确归属的身份证件文字保留在识别全文中，由用户对应填写。诉称、事实部分的金额或上下文不足的内容不直接作出执行金额结论。

识别显示进度并可取消；取消本批次不自动填入本批结果。OCR 初始化或单页处理超过 120 秒时终止，TIFF 另设整份文件 15 分钟上限。读取失败不覆盖已有案件字段，也不会生成演示人名、法院或金额。

## 金额口径

本金是案件页、试算页、Word 和复制页共用的同一个字段。无默认演示本金、利率、日期或合计。

固定年利率试算：

    天数 = 截止日期 − 起算日期 + 1（日历日，包含首尾）
    利息 = 本金 × 年利率 ÷ 100 × 天数 ÷ 365
    合计 = 本金 + 最后一次四舍五入到分的利息

使用十进制整数和精确分数计算，避免浮点误差及夏令时少算一天。本金最多 12 位整数、2 位小数；利率在 0–100% 之间，最多 6 位小数；日期限定为真实的 1900–2100 年日期，区间最长约 100 年。

验算样例均为虚构数据：

| 本金 | 年利率 | 起止日期 | 含首尾天数 | 利息 | 合计 |
| ---: | ---: | --- | ---: | ---: | ---: |
| 100,000.00 | 3.45% | 2026-01-01 至 2026-06-30 | 181 | 1,710.82 | 101,710.82 |
| 125,000.00 | 4.2% | 2026-01-01 至 2026-06-30 | 181 | 2,603.42 | 127,603.42 |

这是一种须由用户核对依据的固定计算口径，不是对所有案件适用的法律计息规则。不自动处理部分履行、抵扣、分期、分段利率、多债权、责任比例、日期争议、法定迟延履行利息或其他费用。“只整理本金”不表示其他请求为零或已经放弃。

## 草稿与导出文件

- **DOCX**：可编辑的真实 Word 文件，包含当事人、执行依据、用户填写请求、独立的拟申请执行法院、签名位置，以及金额和人工核对附录。网页预览与 Word 使用同一份内容映射。
- **ZIP**：默认含 Word 草稿、本地 JSON 草稿、金额记录 JSON、材料清单 TXT、使用说明 TXT，共 5 份文件。只有明确勾选时才加入当前仍在页面内存中的原文件；恢复的文件名索引不会被伪装成原件。
- **JSON 草稿 v2**：保存案件字段、范围回答、计算输入、清单、核对记录、来源和文件索引；v1.1 增加 OCR 方法、参考分数、原识别值和手工修改标记。不保存原文件或全部识别文本。兼容 v1.0 的 v2 草稿及旧演示 v1 草稿，缺项留空。
- **恢复校验**：导入前校验大小（最多 1 MB）、版本、结构、类型、长度、日期和数字；失败时保持现有内容。有效导入也需确认替换，旧合计及所有确认状态不被信任，金额按输入重算后要求重新确认。

输出门槛包括：适用范围、必要案件字段、案件字段确认、有效且已确认的当前计算结果、金额依据及最后的草稿确认。修改上游信息后，旧金额确认和导出确认会撤销。单纯切换到后续页面不能放行下载。

## 隐私与明确边界

文件读取、OCR 和生成均在本机浏览器内完成。应用无案件上传接口、遥测、云端 OCR、外部模型调用或自动提交功能。在线版本从部署服务器获取页面、程序和语言模型；开发模式从本机开发服务器加载代码并连接更新通道。生产环境及本地运行包设有同源内容安全策略，OCR 的程序、模型和 PDF 辅助资源均使用同源路径。官方入口只有用户主动点击时才打开。

原文件、识别全文和工作状态只在当前页面内存中；关闭或刷新后不会自动保留。IndexedDB 只缓存 OCR 语言模型，模型缓存不包含案件图片、文本或字段。主动下载的 JSON 会包含字段及所采纳的来源摘录；JSON、Word、ZIP 都可能含明文敏感资料，不自动加密，请妥善保存，勿公开分享。浏览器扩展、同步设置和系统行为不由本工具控制。

五项执行条件核对是人工记录，不是自动法律审查。工具不作自动管辖、文书效力、主体真实性、法院受理或期限合规结论，不查询法院内部实时状态。

**模板未经法律专业审核，本工具只提供核对草稿，不提供“正式提交版”。** 草稿中保留的“待补充”、事实与理由提示、当事人其他要素及签名日期须在真正提交前按受理法院要求核对处理。

## 构建与验证

    npm test
    npm run build
    npm run build:offline

生产目录为 dist/。public/ocr/ 和运行包均由锁定依赖生成，不提交 Git；已有的需求文档、独立演示及 v1.0 文件不被覆盖。

v1.1 的 36 项自动测试覆盖原有计算和导出规则，以及 OCR 字段规范化、同批冲突、低分及无归属保护、手动修改和清空、长字段草稿往返、图片边界、取消、加载失败和过期响应处理。构建及依赖漏洞检查通过，详见 [更新日志](CHANGELOG.md)。

浏览器使用全虚构材料实测扫描、文本和混合 PDF，20 页 PDF，PNG/JPG/WebP/BMP、多页 LZW TIFF 及 Group 4 黑白 TIFF。两页扫描样本识别到 12 个可填字段，包含第二页的生效日期和本金；这不是对真实案件识别准确率的统计。手动改名、主动清空、识别过程中修改本金、草稿恢复、金额试算、复制和实际 Word/ZIP 下载均已核对。实际下载 Word 的三页已逐页检查中文、金额和分页；桌面和 375×844 窄屏已检查，五页正文无横向溢出。

兼容性证据限定为当前 macOS 的 Codex 内置浏览器及本机 HTTP 运行方式。本地运行包的压缩完整性、解压、启动及 OCR 流程已测试。未通过切断系统网络验证所有浏览器行为；Windows、Safari/Firefox 实机、Vercel 线上完整功能回归和当地法院模板要求不在本次已通过的范围中。

主要依赖及许可证见 [第三方组件说明](THIRD_PARTY_NOTICES.md)。未加入收费 API 或服务；OCR 模型及引擎按需加载，不在打开页面时立即初始化。
